# Print SV — руководство пользователя

Print SV — система для работы рекламно-печатного производства. В ней ведутся заказы, клиенты, материалы, расчёт стоимости, производственные этапы, оплаты, сотрудники и статистика.

Эта инструкция рассчитана на обычного пользователя: что нажать, где найти нужный раздел и что делать при ошибке. Для установки и обслуживания системы есть отдельный раздел в конце документа.

## 1. Вход в систему

1. Откройте в браузере адрес, который выдал администратор. Обычно это `http://<адрес-сервера>:5174`.
2. Нажмите кнопку входа. Откроется страница входа.
3. Введите логин и пароль, выданные администратором.
4. После входа откроется раздел «Заказы» или «Мои заказы» — в зависимости от вашей роли.

Если логин или пароль не подходят, не создавайте новый аккаунт самостоятельно: обратитесь к администратору. Пароль может изменить только администратор.

### Что видно после входа

В верхней панели расположены основные разделы и кнопка выхода. Набор кнопок зависит от роли:

- **Заказы** — общий список заказов.
- **Мои заказы** — заказы, где вы указаны менеджером.
- **Производство** — задания для цеха и этапы изготовления.
- **Уведомления** — сообщения по заказам и комментариям.
- **Admin Panel** — справочники, сотрудники и генерация тестовых данных (только для администратора).
- **Admin Dashboard** — управление компаниями и администраторами компаний (только для роли GOD).

## 2. Роли пользователей

| Роль | Что можно делать |
|------|------------------|
| **ADMIN** | Работа с заказами, клиентами, материалами, операциями, цехами, сотрудниками, статистикой и тестовыми данными в своей компании |
| **MANAGER** | Создание и ведение заказов, работа с клиентами, просмотр своих заказов |
| **PRODUCTION** | Просмотр производственных заданий, изменение этапов изготовления |
| **ACCOUNTANT** | Просмотр заказов, оплат и статистики |
| **GOD** | Работа с компаниями и администраторами компаний; может смотреть данные выбранной компании |
| **USER** | Базовый доступ к своим разделам |

Важно: сотрудники разных компаний не видят данные друг друга. Если вы не находите клиента, заказ или материал, скорее всего, он относится к другой компании.

## 3. Работа с заказами

### Создать заказ

1. Откройте раздел **Заказы**.
2. Нажмите **Создать заказ**.
3. Выберите клиента, укажите описание, срок и параметры заказа.
4. При необходимости добавьте позиции, материалы и операции.
5. Сохраните заказ.

Номер заказа создаётся автоматически. После сохранения заказ появляется в списке и становится доступен производству.

### Найти заказ

В списке заказов можно:

- искать по номеру, клиенту или описанию;
- фильтровать по статусу, менеджеру, клиенту и датам;
- открыть карточку заказа нажатием на строку.

### Статусы заказа

- **Черновик** — заказ создан, но ещё не передан в работу.
- **В работе** — заказ изготавливается.
- **Готов** — работа выполнена, заказ можно выдавать.
- **Закрыт** — заказ завершён.

Статус меняется в карточке заказа. Производственные этапы отмечаются в разделе **Производство**.

### Оплаты, файлы и комментарии

В карточке заказа можно:

- добавить оплату и увидеть остаток долга;
- прикрепить файлы (макеты, документы);
- оставить комментарий и ответить на комментарии коллег;
- посмотреть историю изменений.

Если файл не загружается, проверьте размер: система рассчитана на большие макеты, но браузер и сеть тоже должны выдерживать загрузку.

## 4. Клиенты и справочники (Admin Panel)

Раздел **Admin Panel** доступен администратору компании. Внутри есть вкладки:

- **Клиенты** — добавить, изменить или удалить клиента, указать контактное лицо, телефон, email и процент добавки.
- **Материалы** — список материалов, цены, единицы измерения и коэффициент отхода.
- **Операции** — операции производства и их стоимость.
- **Группы операций** — объединение операций по смыслу, например «Печать».
- **Цеха** — названия цехов и закреплённые за ними операции.
- **Сотрудники** — создание сотрудников, выдача ролей и привязка к цеху.
- **Статистика** — расход материалов за выбранный период.
- **Генерация данных** — создание демонстрационных записей.
- **Конструктор изделий** — шаблоны изделий и расчёт по позициям.

Удаление записей необратимо. Перед удалением система попросит подтверждение. Удаляйте только те записи, которые действительно больше не нужны.

### Сотрудники

При создании сотрудника укажите ФИО, логин, пароль, email и роль. Логин должен быть уникальным. После создания сотрудник может войти в систему со своим логином и паролем.

Если сотрудник перешёл в другой цех или ему нужна другая роль, измените его карточку. Не создавайте дубликат сотрудника с новым логином.

## 5. Производство

В разделе **Производство** отображаются заказы и позиции, которые нужно изготовить.

1. Откройте производственный заказ.
2. Проверьте материалы, размеры и операции.
3. Отмечайте выполненные этапы.
4. Когда все работы выполнены, переведите заказ в статус **Готов**.

Если нужного этапа нет в списке, сообщите администратору: возможно, операция не добавлена в справочник или не привязана к цеху.

## 6. Уведомления

В разделе **Уведомления** отображаются сообщения по комментариям и изменениям заказов. Новые уведомления можно отметить как прочитанные. Кнопка «Отметить все как прочитанные» очищает счётчик.

## 7. Управление компаниями (роль GOD)

Роль **GOD** предназначена для сотрудника, который отвечает за несколько компаний.

В разделе **Admin Dashboard** можно:

- создать компанию;
- изменить название компании;
- удалить компанию;
- создать администратора компании и указать его компанию;
- посмотреть список компаний и их администраторов.

При создании компании автоматически добавляются базовые материалы и операции, чтобы администратор компании мог сразу начать работу.

Будьте осторожны с удалением компании: вместе с ней могут стать недоступны её данные. Перед удалением убедитесь, что данные сохранены или перенесены.

## 8. Генерация тестовых данных

Вкладка **Генерация данных** нужна для демонстрации и обучения. Она доступна только в тестовой среде.

1. Укажите количество записей для нужной таблицы.
2. Нажмите **Сгенерировать**.
3. Для заказов сначала создайте клиентов и сотрудников.

Кнопка **Удалить** удаляет тестовые записи только вашей компании. Действие необратимо.

В рабочей системе генерация тестовых данных должна быть отключена администратором сервера.

## 9. Частые вопросы

### Не открывается страница

Проверьте, что адрес введён полностью, включая порт `:5174`. Если страница не открывается у всех сотрудников, обратитесь к администратору сервера.

### После входа вижу не те разделы

Разделы зависят от роли. Если роль указана неверно, попросите администратора исправить её в карточке сотрудника.

### Не вижу клиента или заказ

Проверьте компанию, в которой вы работаете. Данные других компаний специально скрыты. Если запись точно должна быть видна, сообщите администратору номер записи.

### Сессия завершилась

Войдите снова. Если система часто завершает сессию, проверьте системное время на компьютере — при сильном расхождении вход может не работать.

### Забыл пароль

Обратитесь к администратору: он создаст новый пароль. Самостоятельное восстановление пароля в системе не предусмотрено.

### Ошибка при сохранении

Проверьте обязательные поля и формат данных: телефон, email, числа и даты. Если ошибка повторяется, сделайте скриншот и передайте администратору текст ошибки.

## 10. Для администратора сервера

Этот раздел нужен только тому, кто устанавливает и обслуживает систему.

### Требования

- Docker и Docker Compose.
- JDK 17 и Maven для сборки бэкенда.
- Свободные порты `5174` (сайт) и `8085` (API, только loopback).

### Первый запуск

1. Создайте файл окружения и заполните пароли:

```bash
cp .env.example .env
```

2. Соберите JAR-файлы бэкенда **до** сборки Docker-образов. Dockerfile копирует уже готовые файлы `back/*/target/*-exec.jar`, поэтому без этого шага сборка образов завершится ошибкой:

```bash
mvn clean package -DskipTests
```

3. Соберите и запустите контейнеры:

```bash
docker compose up -d --build
```

4. Проверьте состояние:

```bash
docker compose ps
./scripts/wait-for-stack.sh http://localhost:5174 http://localhost:8085 120
```

Сайт: `http://localhost:5174`. Keycloak и API Gateway опубликованы только на loopback-интерфейсе.

### Тестовая среда и демо-данные

Генератор тестовых данных запускается отдельным профилем:

```bash
docker compose --profile dev up -d generate-data-service
```

Для тестового окружения используйте realm с демо-пользователями:

```bash
KEYCLOAK_REALM_IMPORT=./keycloak/realm-export.dev.json docker compose up -d --build
```

В рабочей среде используйте `./keycloak/realm-export.json` и не запускайте профиль `dev`.

### Обновление

```bash
git pull
mvn clean package -DskipTests
docker compose up -d --build
```

Перед обновлением сделайте резервную копию базы данных. Не удаляйте таблицы `flyway_*_schema_history`: они хранят историю миграций и нужны для корректного обновления.

### Резервное копирование

```bash
docker compose exec -T postgres pg_dump -U postgres svdb > backup_$(date +%F).sql
```

Храните резервные копии вне сервера. Файлы, загруженные пользователями, находятся в каталогах `uploads/` и `images/` — их также нужно копировать.

### Диагностика

```bash
docker compose logs -f api-gateway
docker compose logs -f order-service
docker compose logs -f keycloak
```

Если после обновления сервис не стартует, проверьте логи Flyway: чаще всего причина в недоступной базе или несовпадении истории миграций. Не запускайте `flyway clean` на рабочей базе.

## 11. Технические сведения

- Frontend: React 18 + Vite + Material UI.
- Backend: Java 17, Spring Boot 3.2.5, Spring Cloud (Eureka, Gateway), Spring Security OAuth2.
- Аутентификация: Keycloak 26, OAuth2 Authorization Code + PKCE.
- База данных: PostgreSQL 15, схема `svschema`.
- Мультитенантность: компания определяется атрибутом `company_id` в токене пользователя.
- Миграции: Flyway, отдельная таблица истории у каждого сервиса.
